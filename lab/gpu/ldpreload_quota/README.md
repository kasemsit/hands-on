# lab 49.8 — HAMi ดัก CUDA API ด้วย `LD_PRELOAD` ได้อย่างไร

HAMi บังคับโควตา VRAM ด้วยการแทรก `libvgpu.so` เข้าไปใน container
แล้วดักการเรียก `cuMemAlloc()` ก่อนที่มันจะถึง driver จริง

lab นี้ทำสิ่งเดียวกันแบบย่อส่วน — **ดัก `malloc` แทน `cuMemAlloc`**
จึงรันได้แม้บนเครื่องที่ไม่มี GPU

```bash
make demo
```

## ไฟล์

| ไฟล์ | คืออะไร |
|------|---------|
| `app.c` | โปรแกรมธรรมดา ขอหน่วยความจำ 25 MB แปดครั้ง — **ไม่รู้ว่าถูกดัก** |
| `quota.c` | shim ที่บังคับโควตา 100 MB แล้วคืน `NULL` (= OOM) เมื่อเกิน |

## ผลที่ควรได้

```
=== รันปกติ ===          ครั้งที่ 1-8 สำเร็จหมด
=== รันโดยมี shim ===    ครั้งที่ 1-4 สำเร็จ (4 x 25 = 100 MB พอดี)
                         ครั้งที่ 5 ได้ OOM
```

> `app.c` ปิด buffer ของ `stdout` ไว้ (`setvbuf`) ด้วยเหตุผลสองข้อ —
> ให้บรรทัดของ shim (stderr) เรียงถูกลำดับ และไม่ให้ buffer ภายในของ `printf`
> ไปกินโควตาจนตัวเลขไม่กลม
>
> **นี่เป็นภาพย่อของปัญหาจริง** — CUDA context ก็กินโควตาก่อนที่โปรแกรมจะ
> ได้ใช้เหมือนกัน (บทที่ 47.1)

**โปรแกรมเดิม ไม่ได้แก้โค้ดสักบรรทัด** — เปลี่ยนแค่ environment variable

## ทำไมมันถึงได้ผล

`LD_PRELOAD` สั่งให้ dynamic linker โหลด library ที่ระบุ **ก่อน** library อื่น
ถ้ามีฟังก์ชันชื่อซ้ำ ตัวที่โหลดก่อนจะถูกเรียกแทน

`dlsym(RTLD_NEXT, "malloc")` คือวิธีหา "ตัวจริงตัวถัดไป" เพื่อส่งต่อ
— ถ้าไม่มีบรรทัดนี้ shim จะเรียกตัวเองวนไม่รู้จบ

## ลองต่อ

1. แก้ `QUOTA` ใน `quota.c` เป็น 200 MB แล้วดูว่าตายที่ครั้งไหน
2. เพิ่มการดัก `free()` ให้หักยอดคืน — แล้วลองจอง/คืนสลับกัน
3. ตอบตัวเอง: ถ้าผู้ใช้สั่ง `unset LD_PRELOAD` จะเกิดอะไรขึ้น
   และทำไมข้อนี้ถึงเป็นเหตุผลที่ MIG แข็งกว่า HAMi
